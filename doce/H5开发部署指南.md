# H5 开发部署指南

适用项目：`D:\Pendingweb\todo-h5`。配置核对日期：2026-09-04。

## 1. 项目与运行方式

H5 使用 React、TypeScript、Vite，与 PC 共用后端 API 和权限体系。构建后由 Nginx 提供静态 HTML、JS、CSS；登录、查询、填写、发布仍需要后端和数据库运行。

| 项目 | 目录或地址 | 用途 |
| --- | --- | --- |
| H5 源码 | `todo-h5/src` | 页面、组件、请求与状态管理 |
| H5 开发服务 | `http://localhost:4173` | 热更新，日常开发使用 |
| H5 静态访问 | `http://localhost:8081` | Nginx 读取 `todo-h5/dist` |
| 后端 | `http://127.0.0.1:4000` | 业务接口 |
| PC 静态访问 | `http://localhost:8088` | 当前本机配置，读取 `frontend/dist` |
| Nginx 配置 | `C:\nginx-1.30.2\conf\nginx.conf` | 当前本机生效配置 |

`localhost` 只表示访问设备自己。手机访问电脑服务时使用电脑局域网 IP，例如 `http://电脑IP:8081`，并确认设备同网、端口可达。公网和飞书正式访问使用配置好的 HTTPS 域名。

## 2. 首次准备

当前开发机为 Node.js `v24.13.0`、npm `11.6.2`；这是已核对的环境，不代表项目声明了该最低版本。团队应固定一致版本并使用根目录锁文件安装依赖。

在 PowerShell 执行：

```powershell
Set-Location D:\Pendingweb
npm.cmd ci
npm.cmd run prisma:generate --prefix backend
```

后端需要可用的数据库及相应环境配置。首次配置时参考 `backend/.env.example` 创建 `backend/.env`，填写数据库、JWT、Redis 和飞书相关配置；不要覆盖已有环境文件。环境密钥不得放入前端代码、构建产物或提交到仓库。

数据库初始化、迁移按后端版本单独执行。部署 H5 静态文件不需要重新初始化数据库，也不需要运行 seed。

H5 当前请求地址在 `src/services/http.ts` 中统一为 `/api`。`todo-h5/.env.example` 内的 `VITE_API_BASE` 只是注释示例，代码尚未读取它，单独设置该变量不会改变接口地址。

## 3. 本地开发

两个终端分别启动：

```powershell
# 终端一：从 backend 目录启动，以便读取该目录的 .env
Set-Location D:\Pendingweb\backend
npm.cmd run dev
```

```powershell
# 终端二：H5
Set-Location D:\Pendingweb\todo-h5
npm.cmd run dev
```

浏览器打开 `http://localhost:4173`。Vite 将 `/api` 代理到 `http://127.0.0.1:4000`，端口固定为 4173，冲突时应先确认占用进程。

根目录 `npm run dev` 只启动后端和 PC，不包含 H5。根目录 `start-dev.bat` 另有启动逻辑，并包含释放端口操作；有服务正在使用时，优先用上面的独立命令。

开发查看 4173；验收静态部署查看 8081。修改源码后，8081 必须重新构建才会更新。

## 4. 页面与开发约定

| 路由 | 功能 |
| --- | --- |
| `/login`、`/identity` | 登录与身份选择 |
| `/dashboard` | 仪表台 |
| `/todos` | 我的待办 |
| `/publish` | 任务类型选择 |
| `/publish/workflow` | 流转任务发布 |
| `/publish/broadcast` | 群发任务发布 |
| `/publish/temporary` | 临时任务·触达式发布 |
| `/auth/callback`、`/feishu-entry` | 飞书登录相关入口 |

- 路由在 `src/App.tsx` 注册，页面通过 `React.lazy` 按需加载。
- 共用请求层附带 Bearer Token 和 `X-Identity-Id`；前端隐藏入口不代替后端鉴权。
- 身份状态位于 `src/stores/auth.ts`，使用持久化存储。切换身份时不要复用上一个身份的业务缓存。
- 发布页尽量复用 `PublishHeader`、题型编辑样式、预览反馈及底部导航。
- 加载失败应提供重试；写操作应防重复提交，失败保留可重试的输入。
- 模拟测试不能代替真实权限联调。联调发布操作使用明确授权的测试账号和接收人。

### 当前发布能力

流转任务按节点依次执行；群发任务使用同一套题目，由接收人独立填写。两者沿用后端接收范围校验。

H5 临时触达式仅支持搜索指定账号投放，截止时间必填。已有模板选择、组织范围投放、二次通知、手动保存/恢复草稿、重开任务入口均已移除。预览内部仍复用服务端模板和临时草稿协议，不能将“无草稿按钮”理解为“不产生任何内部草稿”。

### 分级加载与缓存

| 页面 | 当前加载方式 |
| --- | --- |
| 流转发布记录 | 分类按需请求，每页 10 条；每页响应包含节点及题目等详情，展开不是独立详情请求 |
| 群发发布记录 | 分类每页 10 条；展开任务后每页获取 10 位接收人及答案 |
| 临时触达记录 | 分类每页 10 条；展开任务获取 10 位接收人，展开接收人再获取答案 |

临时触达页在当前页面生命周期内缓存分类、接收人和答案，有效期 1 分钟；切换分类、重复展开可复用已加载内容。刷新、发布成功、终止任务后清除缓存；身份或基地切换时隔离。超过有效期后再次访问才重新加载，不是每分钟后台轮询。

## 6. 当前本机静态部署

当前 Nginx 直接读取 `D:/Pendingweb/todo-h5/dist`。本机更新步骤：

1. 执行 H5 build，并确认成功退出。
2. 打开或刷新 `http://localhost:8081` 验收。
3. 仅替换静态文件通常不需要重启 Nginx；修改 Nginx 配置后先检查再重载。

```powershell
Set-Location C:\nginx-1.30.2
.\nginx.exe -t
# 仅在上一步检查成功后执行；未启动时先启动服务
.\nginx.exe -s reload
```

仓库 `deploy/nginx.conf.example` 是参考配置，PC 示例端口是 8080，与当前本机的 8088 不同，不要直接覆盖生效配置。

H5 server 的关键规则如下（放入现有 Nginx http 配置内，路径按目标机器调整）：

```nginx
server {
    listen 8081;
    server_name localhost;
    root D:/Pendingweb/todo-h5/dist;
    index index.html;

    location = /index.html {
        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, max-age=2592000, immutable";
        try_files $uri =404;
    }
    location / {
        try_files $uri $uri/ /index.html;
    }
    location /api/ {
        proxy_pass http://127.0.0.1:4000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

`proxy_pass` 此处不添加末尾 `/`，以保留后端要求的 `/api/...` 路径。`/assets/` 缺失文件必须返回 404，不能回退成 HTML。业务路由需要回退到 index.html，否则直接刷新 `/dashboard` 等地址会 404。

附件还需沿用目标环境的上传与下载配置。当前本机另有 `/uploads/` 映射；不要将需要鉴权的下载接口随意改为公开静态目录。若上传返回 413，核对 Nginx `client_max_body_size` 和后端限制，两者都要覆盖业务允许的文件大小及 multipart 开销。

## 7. 更新、旧资源与回滚

### 为什么长时间打开的页面可能失败

已打开页面持有旧版 JS 的引用。重新构建若清空 dist，用户之后切换尚未加载的路由时会请求已删除的旧文件，产生动态模块加载失败。实际排查曾在 Nginx access.log 中发现旧版 `DashboardPage-*.js` 返回 404。

当前 `vite.config.ts` 已设置 `build.emptyOutDir: false`，本机重复构建会保留旧资源。不要在构建前清空正在服务的 dist，也不要在同步时用删除模式清理旧 assets。

这一设置只保护目标目录中已存在的资源：全新 CI 工作区或新服务器构建并不会自动拥有历史文件。

### 正式环境发布建议

1. 在独立目录构建并验证，保留版本号、提交号及完整产物。
2. 将新版本 assets 增量上传到公共资源目录，同时保留旧版哈希资源。
3. 所有新资源可访问后，再以原子替换方式更新 index.html；不要先发布入口再上传 JS。
4. 保留上一版入口文件及其依赖资源，必要时回滚入口；后端接口也应兼容仍在线的旧前端。
5. 验证新窗口访问及旧标签页切换路由。静态更新不要求重新登录。

本机直接向正在服务的 dist 构建不属于原子发布；正式环境应采用上述分阶段发布流程。

旧资源需要定期清理，当前没有自动清理任务。保留周期应覆盖团队约定的旧标签页支持窗口，并结合访问日志制定；不要仅凭“上个版本”判断可删。超过保留窗口的页面应引导重新载入。历史资源占用增加的是服务器磁盘，浏览器不会因此全量下载它们。

## 8. 常见故障定位

| 现象 | 优先检查 | 处理 |
| --- | --- | --- |
| 长时间打开后切换页面失败 | Network 中旧哈希 JS 404、动态模块加载错误 | 刷新当前页；检查是否清空/遗漏历史 assets |
| API 返回 401 | 登录令牌有效性、后端鉴权日志 | 重新登录；核对真实 JWT 配置 |
| API 返回 403 | 当前身份及服务端权限 | 选择正确身份或核查授权，不应直接判定为登录过期 |
| API 返回 502 | 4000 端口和 Nginx upstream | 恢复后端服务并检查代理地址 |
| 修改源码但 8081 未更新 | 是否单独构建 H5、Nginx root 指向 | 构建 H5，确认新 index.html 和资源已发布 |
| 直接刷新业务路由 404 | Nginx SPA 回退 | 配置 `try_files ... /index.html` |
| API 响应被当成 HTML | `/api` 路径和代理尾斜杠 | 修正代理，不能返回前端入口 |
| 飞书登录回调失败 | 应用配置、HTTPS 域名和 H5 回调地址 | 核对实际部署地址与飞书后台白名单 |

后端 JWT 配置默认值为 8 小时，实际有效期以运行环境为准。当前 H5 请求层尚未统一处理 401 自动退出，也没有自动续期机制；不能把通用页面错误提示直接当成 Token 失效。

页面错误边界位于 `src/components/PageErrorBoundary.tsx`，资源加载错误会提供重新载入提示。排查时结合浏览器 Console、Network 与 Nginx `logs/access.log`、`logs/error.log`，不要仅凭提示文案判断原因。日志分享前去除 Token、账号等敏感信息。
