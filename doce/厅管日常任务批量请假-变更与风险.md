# 厅管日常任务批量请假

## 使用方式

在厅管日常任务看板选今天，展开团队，勾选厅或选择团队内有任务的厅，点击批量请假或批量取消请假。两种操作都必须填写原因并确认日期及名单。每批最多100份任务，超过时分批处理。只处理已有当天任务记录，不为无任务的厅生成虚假任务。

团队管理仅本团队，基地及以上管理在授权组织范围内操作。厅管不可直接批量批准。豁免对象是整厅当天任务，不是厅管个人出勤。

## 规则与存储

- 复用 HallTaskLeaveRequest，无数据库迁移。
- 已完成跳过、已批准跳过；待审记录原申请人和原因保留，追加管理批准意见；无待审记录时记录管理直接批准来源。
- 取消将 pending/approved 记录标为 cancelled，不删除申请；保留批准信息，在 reviewComment 追加操作人ID、UTC时间和取消原因。
- 批量预检日期、全部目标权限、数量；实际写入逐厅事务，返回 approved/cancelled/completed/already_approved/not_enabled/stale_record/failed 明细。
- 任务记录变更时重新校验看板所选记录是否仍为当天优先记录；更新后需刷新重选。
- 批准、取消、原有申请审批、答题、提交及附件修改共用 MySQL 记录行锁，避免请假与提交同时成功。
- 已批准请假锁定填报和附件修改；取消不清空原答案，也不延长补录截止时间。

## 统计

厅管看板团队/基地汇总及仪表台厅管历史区间统一为完成厅次 / (应完成厅次 - 已批准请假厅次)，百分比四舍五入。待审、拒绝、取消不排除分母。

接口全豁免时保留数字0以兼容消费者，厅管管理看板展示“—（无需考核）”。历史统计按新公式重算，不改历史原始记录，数值可能与旧页面不同。未发现厅管日常专用的未完成催办实现，本次没有新增通知系统。

## 风险和上线

风险中等：改变历史统计展示；整厅共享任务会同时影响该厅所有厅管；长批次可能部分成功。应先在测试环境验收，且后端必须全部实例同时发布（旧实例不使用行锁，会削弱并发保护）。无需重建数据库。

验证：前后端 TypeScript 检查；backend/tests/hall-batch-leave.test.ts 使用隔离内存数据测试权限、日期、幂等、跳过已完成、待审保留、取消历史、部分失败重试、提交冲突。模拟事务测试不替代真实 MySQL 并发及浏览器验收。

本次不自动构建覆盖静态目录或重启生产。上线需后端编译重启、前端构建发布；保留上一版发布产物便于回滚。回滚代码不会自动撤销已批准请假，需按审核后的目标另行取消。
