# 团队管理日常任务

## 业务与入口

基地管理员、总部管理员、开发管理员在「任务发布 → 团队管理日常任务」选择基地、维护表单、选择目标团队并发布。团队管理员在 PC 或 H5「我的待办」共同填写本团队的每日任务，由任一成员明确提交。每道题记录填写人，整份记录记录提交人。

PC 看板入口为「任务看板 → 团队管理日常任务看板」：基地及以上管理员查看管辖基地汇总、团队进度、作答和请假审批；团队管理员只查看当前团队。

## 业务约束

- 一条生效任务下，每团队、每个北京时间日期只有一条共享记录，不按管理员人数生成。
- 同基地仅一条生效任务，最多一条待生效任务。新任务立即生效时结束旧任务；次日生效时，到北京时间零点才替换旧任务。
- 同一天更换任务保留旧记录，看板优先展示生效任务；旧任务当天不可继续填写。
- 立即发布时同步生成当日记录；定时器每分钟激活到期任务并幂等补建当日记录。
- 昨日记录可补录到次日北京时间 16:00；换版后的昨日历史记录仍可补录。
- 共享填写不是实时推送；刷新页面、点击刷新或回到 PC 窗口可获取他人更新。同一题先后保存以最后一次成功写入为准。
- 填写、提交及附件操作按账号下活跃团队管理身份校验，不要求当前选中该身份；待办汇总账号所属团队的任务，无权限或身份停用时不能操作。
- 请假针对整个团队当天的记录，由基地及以上管理员审批。批准后不能继续填写或提交。
- 完成率为 `已提交团队数 / (参与团队数 - 已批准请假团队数)`；全部请假显示无需考核。
- 多人同时提交、请假审批和作答通过数据库行锁串行化。

## 代码与数据

- 后端：`backend/src/modules/task/team-daily/`，API 前缀 `/api/team-daily`。
- 报表：`/api/tasks/report/team-daily-dashboard` 及其 overview、团队列表和详情接口。
- 图片：`/api/tasks/team-daily/upload`、`/api/tasks/team-daily/attachments/:id`，支持 JPG/PNG/GIF/WebP，单张不超过 1MB。
- 发布页：`frontend/src/pages/tasks/manage/TeamDailyIssuePage.tsx`。
- 看板：`frontend/src/pages/tasks/dashboard/TeamDailyDashboardPage.tsx`。
- PC 执行：`TeamDailyTodoSection.tsx`、`TeamDailyRecordCard.tsx`。
- H5 执行：`/todos?category=team`、`/todos/team/:id`。
- 数据表：独立的 `team_task_*` 九张表，与厅管日常数据隔离；模板和发布归属 `baseOrgId`，目标和执行记录归属 `teamOrgId`。
- 本期 H5 支持执行，发布和管理看板在 PC。

## 发布步骤

1. 按现有运维流程备份数据库，检查迁移历史。
2. 在 `backend` 下运行 `npx prisma migrate deploy`，应用 `20261022000000_add_team_daily_tasks`。该迁移仅创建九张新表及其索引、外键，不更改原有表数据。若历史迁移异常，应先核对历史，不要使用 reset。
3. 运行 `npm run prisma:generate --prefix backend`。Windows 若运行中的后端占用 Prisma 引擎，需在维护窗口停止后端后重新生成。
4. 根目录运行 `npm run build`，另运行 `npm run build --prefix todo-h5`。
5. 重启后端，按既有部署流程更新 PC/H5 静态文件。没有执行迁移时不可将新版本当成已上线。

回滚应用版本时保留新增表，避免丢失已填写数据；不自动删除任务表。

## 验证

- 根目录：`npm run typecheck`、`npm run typecheck --prefix todo-h5`。
- 本机 MySQL 集成测试：在 backend 目录设置 `TEAM_DAILY_INTEGRATION=1`，运行 `npx tsx tests/team-daily.integration.ts`。
- 测试仅接受本机数据库连接，创建独立 `team_daily_test_*` 数据库、生成完整测试结构，测试结束后删除该测试库，不写入现有业务库。需要本机账号具有建库权限及本地 Prisma 引擎。
- 覆盖共享记录、不同填写人、并发提交、跨团队/基地权限、请假、统计、补录截止及次日激活。
