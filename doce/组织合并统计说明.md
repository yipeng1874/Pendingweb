# 组织合并统计

入口：组织管理 → 合并统计。开发管理员、总部管理员、基地管理员可使用，要求 org:update 权限；基地管理员只能配置自己的管理范围。

选择基地，新建分组并输入名称，再通过“添加团队”选择未分组团队加入，最后保存配置并刷新仪表台。支持先保存空组，之后添加团队；空组不会出现在统计中。组内仅展示已加入成员，可移出。已经加入 A 组的团队不能再加入 B 组，必须先移出或解除原组。可修改、停用、解除分组，停用组仍保留成员。

## 范围与口径

- 仅应用于仪表台主播、厅管日常任务历史完成率的团队明细，包括昨天、近三天、近七天、本月、自定义范围。
- 按当前配置合并历史展示，不迁移组织、账号、任务或原始历史记录。
- 各团队的完成数、参与数、豁免数先相加，再计算完成率；分母为参与减豁免。不平均百分比。
- 合并行可展开查看原始团队明细，基地总量不变。
- 只处理原接口已授权的数据；单团队权限仍显示原团队，不获得其他团队数据。
- 配置保存有版本冲突校验及审计日志，事件为 STATISTICS_GROUPS_UPDATE。
- 配置读取异常时记录 statistics_groups_read_failed 错误日志，统计退回原团队明细，避免影响报表可用性。

## 部署

先在 backend 目录执行新增表脚本（幂等、只建新表，不修改历史表）：

```powershell
npx prisma db execute --file prisma/statistics-groups.sql --schema prisma/schema.prisma
```

然后构建前后端，重新加载后端服务。Prisma 模型已同步登记；当前功能用参数化 SQL 访问此独立配置表，不依赖重新生成客户端。

回退可停用全部分组或恢复旧应用代码；新增配置表可保留，不必删除。
