# todo-h5

独立于现有 PC 项目的 H5 前端，包含仪表台、我的待办和任务发布。

完整操作说明见 [H5 开发部署指南](../doce/H5开发部署指南.md)，涵盖开发启动、静态部署、旧资源保留、回滚及故障排查。

## 当前已实现
- 账号密码登录
- 飞书登录入口与回调处理
- 登录后身份选择
- 我的待办列表
- 七类待办展示及填写：主播日常、厅管日常、触达式、主播式、管理式、流转任务、厅内直达
- 图片上传前自动压缩：超限照片按比例缩小并转为 JPEG，预览确认后上传；1MB 内的支持格式保持原文件，失败可重试

## 当前原则
- 不改现有 `frontend` 项目页面文件
- 复用现有后端 API
- 先跑通 `登录 -> 身份 -> 我的待办` 主链路

## 启动
```bash
cd todo-h5
npm install
npm run dev
```

默认开发端口：
- `http://localhost:4173`

代理后端：
- `/api -> http://127.0.0.1:4000`

## 图片压缩验证
启动开发服务后，打开 `http://localhost:4173/tests/imageCompression.html`。
测试在浏览器本地生成图片，不发送上传请求，覆盖大图压缩、尺寸比例、小图原样返回、EXIF 竖拍方向、透明背景及异常格式。

HEIC/HEIF 需要浏览器能解码；不支持时会提示改用 JPG/PNG/WebP。超过 1MB 的 GIF 不自动转成静态图。

## 待办填写规则

| 类型 | 填写入口及完成方式 |
| --- | --- |
| 主播日常、触达式、主播式、管理式 | 点击任务进入详情；问答、单选、多选、待办确认、学习链接、图片上传复用普通待办接口。必填项完成后可在底部提交；后台也会在全部子项完成时自动完成。 |
| 厅管日常 | 点击任务进入详情；使用厅管专属保存和上传接口，必填项完成后自动提交，失败时可在底部重试。支持次日北京时间 16:00 前补录。 |
| 流转任务 | 展开后填写本人负责且未完成、未截止的节点。待办题填写完成情况说明；逐题确认，全部必填题确认后自动完成节点。其他人的节点只读。 |
| 厅内直达 | 展开后逐题确认，全部必填题确认后自动完成；已结束或已截止时只读。 |

流转任务和厅内直达共用六种题型编辑器，已确认答案只读。附件支持图片及后台允许的 PDF、Word、Excel、MP4、MOV，单文件上限 20MB；静态照片超过 1MB 自动压缩并预览，GIF 保留原图。普通任务及厅管日常图片仍限 1MB。

已提交的个人任务、日常任务只读；组织临时任务保留提交后补充能力。厅管请假待审核或已批准、主播日常已豁免时只读。未确认输入保留在当前展开页面，离开页面前请先确认保存。

## 填写流程验证

启动开发服务后打开 `/tests/taskFilling.html`。浏览器测试使用模拟接口，覆盖七类入口、六种题型、失败重试、图片/文档上传关联、自动完成及完成分组、权限和补录规则、手机宽度溢出检查。`/tests/taskFilling.html?preview` 可查看模拟流转填写界面。这些测试不代替真实账号的后端联调。

页面加载回归可打开 `/tests/pageLoading.html`，验证真实仪表台路由懒加载及空模块异常的恢复提示。开发服务等待文件写入稳定后再更新模块，避免保存过程中短暂的空文件进入转换缓存。

## 流转任务发布

有 PC 流转发布权限的五类管理身份，可从底部「任务发布」进入 `/publish`。基本信息、节点配置、预览确认三步发布，支持六种题型；「我发布的」可查看节点进度和执行答案。初始化仅使用当前登录身份，不下载全量人员；输入有效关键词后防抖搜索（文字至少2字、纯数字至少5位，最多20人）。共用 PC 的执行人搜索和创建接口，后端校验身份与执行人范围；不修改流转执行规则。发布表单仅保留在当前页面，切换身份后清空。

「我发布的」使用 `issued-page` 接口，默认只请求进行中的前10条；已完成、已结束在切换分类后才请求，每次点击「加载更多」追加10条。后端按发布人及任务状态过滤并使用游标分页，过期任务归入已结束；PC 原 `issued` 接口保持兼容。

开发服务下打开 `/tests/workflowPublish.html` 运行隔离模拟测试，覆盖角色入口、字段校验、六题型请求、身份请求头、失败重试、重复提交、发布结果只读和身份切换。`?preview` 查看基本信息，`?preview=nodes` 查看节点编辑。测试不发送真实发布请求，也不写入登录凭据。

## 群发任务与类型入口

`/publish` 为独立类型选择页，流转发布位于 `/publish/workflow`，群发发布位于 `/publish/broadcast`。群发遵循 PC 权限：厅管可选本厅主播或同基地其他厅管，团队管理仅可选同基地厅管；其他身份不显示群发入口，后端继续验证接收人范围。

群发支持基本信息、选择接收人、配置六种题型、预览发布四步，H5 截止时间必填，发布前核对5秒。本厅主播进入配置时直接分页展示20人并支持多选；厅管搜索分页20条，已选人员在弹窗内保持可见，不调用全量 bootstrap；发布历史按状态分页10条，展开任务后分页获取10位接收人及答案。切换身份清空表单，离开页面不保留草稿。

隔离验证：开发服务打开 `/tests/broadcastPublish.html`；后端执行 `node --import tsx --test tests/broadcast-mobile.test.ts`。使用模拟接口/数据库，不发布真实任务。

## 临时任务：触达式

入口为 /publish/temporary，访问按服务端 task:assignment:manage 权限控制，模板编辑另校验 task:template:manage。基地用于权限和数据范围，接收人仅支持搜索指定账号。

四步为基本信息、接收账号、配置题目、预览发布；截止时间必填。已移除已有模板选择、组织投放、二次通知、手动草稿管理和重开任务入口。预览内部仍复用服务端模板与临时草稿协议，正式发布需用户确认；进行中的任务可终止。

分类列表每次 10 条，展开任务分页获取 10 位接收人，展开接收人再请求答案。当前页面内缓存有效期 1 分钟，切换分类和重复展开复用缓存，刷新、发布成功或终止后清除；身份和基地之间隔离缓存。

开发服务下可打开 /tests/temporaryPublish.html 进行模拟接口验证，不创建真实任务。缓存回归执行 node todo-h5/tests/publishCache.test.mjs（从项目根目录运行）。浏览器测试断言应随功能调整维护，以实际运行结果为准。
